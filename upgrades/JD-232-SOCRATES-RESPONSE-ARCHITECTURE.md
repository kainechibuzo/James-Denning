# JD-232 — Socrates-inspired response architecture

- **Created:** 2026-11-13
- **Status:** implemented in source; CI/staging verification pending; not deployed.
- **Reference project:** `kainechibuzo/socratesintelligence`.

## Adopted patterns

1. SSE text deltas from the OpenRouter Responses API.
2. Task-aware model selection with explicit operator-configured fast and reasoning model rungs.
3. Bounded continuation when the provider ends a response with `incomplete_details.reason=max_output_tokens`.
4. Staged document output through a dedicated file tool rather than pretending a generated document was saved.
5. Per-request time-to-first-token and total latency telemetry.

## JD-specific implementation

- `jd-agent-stream.ts` parses Responses API SSE and exposes only user-visible text deltas. It also returns the terminal response for usage accounting and tool calls.
- `jd-execution-worker` writes partial text into a job-linked `jd_messages` row, throttled to 800 ms. The authenticated job-status action returns that row while active; ChatHome already polls each active job every three seconds and now displays the partial text.
- The runtime checkpoints continuation text/count and the active model. It continues at most twice. Incomplete function-call output is never executed.
- `jd-agent-routing.ts` classifies quick, balanced and reasoning work. Optional `JD_MODEL_FAST_NAME` and `JD_MODEL_REASONING_NAME` secrets are used only when configured; otherwise `JD_MODEL_NAME` (default `openrouter/free`) remains in effect.
- `create_business_document_draft` saves a new private `.txt` draft to the existing `jd-business-documents` bucket and records it in `jd_business_documents`. The tool is limited to admins, managers and bursars. Drafts are capped at 95 KB and use generated tenant-scoped paths.
- The run monitor shows average first-token latency when provider requests report text deltas.

## Deliberately not copied

Socrates' tool loop handles one detected tool call per round. JD already supports parallel execution of independent tool calls, so its existing parallel function-call handling is retained.

## Safety and non-goals

- No queue, lease, retry, checkpoint RPC, tenant scope or approval semantics were removed.
- The document tool creates a private draft only; it does not send, publish, delete or modify business records.
- Only plain-text `.txt` drafts are supported by this new tool. It does not implement a multi-file source-code workspace, PDF/DOCX export or chat file uploads.
- No database migration, production secret change or production deployment was performed.
